# Нативное приложение T2 Sales (Windows и Android)

[Каталог документации](../docs/README.md) · [Обзор проекта](../README.md)

Два полноценных клиента T2 Sales на общем коде Kotlin Multiplatform: Compose Multiplatform for Desktop (Windows) и Compose для Android — модуль `androidApp` ([docs/ANDROID.md](docs/ANDROID.md)). Это отдельная кодовая база: она не использует веб-страницы и не заменяет Electron-приложение из `desktop/` или Capacitor-обёртку из `android/`, а работает с тем же рабочим сервером и повторяет веб-версию экран за экраном. Документ — точка входа для тех, кто запускает, собирает или дорабатывает эти клиенты; этот README и большинство документов в `docs/` описывают в первую очередь клиент для Windows — Android-специфика (устройство, экраны, сборка, что проверено) вынесена в [docs/ANDROID.md](docs/ANDROID.md).

## Что это

| Параметр | Значение |
| --- | --- |
| Версия | `1.2.0` — ведётся отдельно от веба и backend; единственный источник — `appVersion` в [desktopApp/build.gradle.kts](desktopApp/build.gradle.kts) |
| Платформа | Windows 10/11, x64 (клиент для ПК); Android 7+ (отдельный модуль `androidApp`). Общий слой `shared` не привязан к Windows |
| Стек | Kotlin 2.0.21, Compose Multiplatform 1.7.1, Ktor 2.3.13 (OkHttp), kotlinx.serialization 1.7.3 |
| Сервер | `https://tele2-app-production.up.railway.app` (см. `ApiConfig` в `shared`) |
| Оформление | Повторяет веб (`styles.css`): светлая и тёмная темы, переключатель в шапке |
| Установка | Один `.exe` на пользователя, без прав администратора: [installer/README.md](installer/README.md) |
| Обновление | Проверяется и ставится при запуске: [docs/UPDATES.md](docs/UPDATES.md) |

Электрон-приложение продолжает работать без изменений. Нативный клиент устанавливается в свою папку под своим именем (`T2 Sales Native`) и не пересекается с ним.

## Быстрый старт

Нужен JDK 17. Рабочий каталог — `native/`, оболочка — Git Bash или PowerShell.

```bash
export JAVA_HOME="/c/Users/<пользователь>/tools/jdk-17.0.20.1+1"   # пример пути
export PATH="$JAVA_HOME/bin:$PATH"

./gradlew :desktopApp:run            # запустить из исходников (со сплэшем)
./gradlew :desktopApp:compileKotlin  # быстрая проверка, что всё собирается
./gradlew :shared:jvmTest :desktopApp:test   # тесты
./gradlew :desktopApp:packageSetup   # собрать установщик
```

Установщик появляется в `desktopApp/build/installer/T2SalesNative-Setup-x64-<версия>.exe`. Подробности, переменные окружения и режимы отладки — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Где приложение хранит данные

| Что | Где |
| --- | --- |
| Сессия (cookie `t2_session` и `t2_csrf`), зашифрована DPAPI | `%USERPROFILE%\.t2sales\cookies.json` |
| Выбранная тема, режим сети | Реестр Windows, узел Java Preferences `ru/t2sales/desktop` (`HKCU\Software\JavaSoft\Prefs`) |
| Сессия защищена DPAPI: файл зашифрован для вашей учётной записи Windows | `cookies.json` (см. выше) |
| Последние ответы главной и графика (кэш чтения) | `%USERPROFILE%\.t2sales\cache\<id сотрудника>\` |
| Размер и положение окна, «закрытие сворачивает в трей», уже показанные уведомления | Реестр Windows, Java Preferences `ru/t2sales/desktop` (и `ru/t2sales/desktop/notify`) |
| Автозапуск с Windows (если включён) | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение «T2 Sales Native» |
| Очередь неотправленных продаж | `%USERPROFILE%\.t2sales\pending-sales.json` |
| Последние данные формы «Добавить продажу» (для работы без сети) | `%USERPROFILE%\.t2sales\sale-form-cache.json` |
| Журнал обновлений | `%LOCALAPPDATA%\T2 Sales Native\logs\updater.log` |
| Скачанные установщики | `%LOCALAPPDATA%\T2 Sales Native\updates\` |
| Само приложение (после установки) | `%LOCALAPPDATA%\Programs\T2 Sales Native\` |

## Ограничения

- Клиент для Windows: только x64, проверялось на Windows 11.
- Клиент для Android: минимальная версия Android 7 (API 24); в RuStore пока опубликовано прежнее Capacitor-приложение (`android/`), нативный клиент — версия для разработки (`2.0.0-dev`), см. [docs/ANDROID.md](docs/ANDROID.md).
- Автоматических тестов интерфейса нет ни у одного из клиентов: экраны проверяются вручную по снимкам окна/телефона (см. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#проверка-интерфейса) и [docs/ANDROID.md](docs/ANDROID.md#что-проверено-и-что-нет)).
- Реальное обновление «с сервера на новую версию» целиком (загрузка, установка, перезапуск) в живой среде не прогонялось на клиенте для Windows: проверены части по отдельности и демо-режим. Подробнее — в [docs/UPDATES.md](docs/UPDATES.md). У Android-клиента механизма автообновления пока нет вовсе.

### Реальный случай: установка на корпоративный ПК блокируется без прав администратора

Установщик Windows-клиента **не подписан цифровой подписью Authenticode** —
политика проверки обновлений `warn` допускает отсутствие подписи у самого
приложения, но блокирует повреждённую подпись у скачанного обновления (это
два разных, не связанных механизма — см. [docs/UPDATES.md](docs/UPDATES.md)).

На обычном домашнем ПК это просто предупреждение SmartScreen с кнопкой
«Всё равно запустить». На реальном корпоративном ПК с жёсткой политикой это
предупреждение оказалось непроходимым для обычного (не администраторского)
аккаунта — при этом сам установщик по коду **не запрашивает** повышение
прав: манифест `installer/setup/app.manifest` явно требует
`requestedExecutionLevel level="asInvoker"`, ставит в
`%LOCALAPPDATA%\Programs\...`, пишет только в `HKEY_CURRENT_USER` —
блокирует не сам установщик, а внешняя система репутации Windows.

Ключевая находка при диагностике этого конкретного случая: **старая
Electron-версия того же приложения (тоже официально неподписанная,
см. `desktop/electron-builder.yml`) на этом же ПК ставилась без прав
администратора**, а свежесобранный нативный установщик — нет. Причина не в
подписи (её нет ни у одного из двух), а в том, как Windows SmartScreen
считает репутацию файла: **по хэшу конкретного файла, а не по программе в
целом**. Electron-инсталлятор существует и раздаётся давно — успел набрать
репутацию у большого числа установок; каждая новая сборка нативного
установщика — технически новый файл с нулевой репутацией (в него
зашивается свежий `payload.zip`, хэш меняется на каждый релиз), поэтому
она каждый раз проходит проверку заново, «с нуля».

Единственное постоянное решение — код-подпись сертификатом (лучше EV: он
даёт репутацию сразу, а не постепенно набираемую по хэшу). Временный обход
на конкретном ПК, пока сертификата нет: попросить IT-отдел либо один раз
запустить именно этот файл под администраторской учётной записью (после
установки приложение работает от обычного пользователя — права нужны
только чтобы один раз пройти проверку SmartScreen), либо занести SHA-256
конкретной версии файла в исключения корпоративного Defender/AppLocker —
второй вариант приходится повторять на каждый новый релиз, пока нет
сертификата.
