# Нативное приложение для Android

[Каталог документации](../../docs/README.md) · [Нативный клиент](../README.md)

Нативный клиент T2 Sales для телефона на Kotlin и Compose: те же данные и тот же сервер, что в веб-версии и в клиенте для Windows, но собственный мобильный интерфейс с нижней навигацией. Модуль `androidApp`. Пока это разработческая версия (`2.0.0-dev`): в RuStore лежит прежнее приложение-оболочка на Capacitor (`android/`), и оно остаётся, пока нативное не выйдет на паритет.

## Устройство

- **`shared`** получил цель Android. Сеть, модели, вход и тема общие с клиентом для Windows. Отличия по платформам: сессия (cookie) на Windows шифруется DPAPI, на Android — ключом Android Keystore (AES-256-GCM); каталог данных — `filesDir/t2sales`.
- **Навигация.** Шесть вкладок как в мобильном вебе: Главная, План, График, Профиль, Команда, Чат. Остальные экраны (`Page` в `ui/Nav.kt`) открываются поверх вкладок со стрелкой «‹»; `AppNav.go(Screen)` переводит общую модель навигации в вкладку или страницу. У роли «Супервайзер» своя нижняя навигация (Обзор, Точки, Люди, Тренд, Профиль), как в вебе.
- **Листы.** `BottomSheet` рисуется общим слоем `SheetLayer` в корне оболочки (не отдельным окном): так он закрывает нижнюю навигацию, учитывает жестовую панель и клавиатуру и закрывается кнопкой «Назад».
- **Офлайн-очередь продаж** (`offline/SalesOutbox.kt`, лист `ui/OutboxUi.kt`): продажа, внесённая без связи, сохраняется в файл и уходит сама; повтор не удваивает продажу (сервер дедуплицирует по `client_id`), реальное время продажи сохраняется в `occurred_at`. Индикатор «В очереди: N» в шапке главной.
- **Файлы.** Экспорт CSV и картинки-отчёты уходят в системное окно «Поделиться» (`ui/FileShare.kt`, `FileProvider`); отчёт-картинка рисуется из SVG библиотекой AndroidSVG. В чате можно прикреплять файлы (системный выбор) и открывать вложения.

## Экраны

Все экраны веба перенесены: Главная (с «Калькуляторами», «Быстрыми действиями», «Инструментами» и виджетом «Сеть за минуту» для manager/admin/supervisor), План дня, График (со сводным графиком команды и автоматическим расчётом графика для тех, кто его правит — черновик, применение, «Требования к покрытию», «Недоступность/отпуск»), Профиль (с загрузкой аватарки), Команда (с блоком «Управление», карточкой сотрудника, сменой ролей, переключателем «Дилер/Сектор/Сеть» для администратора), Чат, BFQ, Задачи, Алерты, Объявления, Поддержка, Касса, История продаж, Планы и факт за месяц, Динамика выполнения, Отчёты, Отчёт-картинка, Сеть live, Heatmap, Прогноз и what-if, Повтор месяца, Command Center, Профиль точки, экраны супервайзера, Сети, История действий, Дилеры/Секторы, Admin Center (все 12 вкладок: Обзор, Сотрудники, Точки, Коррекции продаж/смен/графика/планов, Флаги функциональности, Настройки сети, Бизнес-правила, Операционный центр, Аудит). Форма добавления продажи, открытие и закрытие смены, калькуляторы комбо и школа, промокоды РТК.

## Как работает перенос экранов

Экраны с общей логикой не переписывались с нуля, а копировались из десктопного клиента (`desktopApp/.../ui`) в `androidApp/.../ui/ported` со сменой пакета и импортов; вёрстка адаптирована под телефон. Общие компоненты десктопа продублированы под теми же именами в `ui/Compat.kt`: `Field`, `MainButton`, `SheetDialog`, `DropdownField`, `PageSection`, `MChipButton`, `WideTable` и др. Разбор динамических JSON — `ui/JsonUtil.kt` (`obj`, `arr`, `dbl`, `str`, они одни на пакет: частные копии с одной сигнатурой в разных файлах конфликтуют).

Широкие таблицы оборачиваются в `WideTable`: у них остаётся читаемая ширина колонок, и они прокручиваются вбок.

## Анимации и скорость

**Анимации** (`ui/Motion.kt`, тот же словарь движения, что у клиента для Windows): вкладки плавно появляются, страницы въезжают справа и уезжают обратно, листы поднимаются снизу над затемнением и плавно закрываются, кнопки и строки списков «проседают» при нажатии (пружина), значок активной вкладки подпрыгивает и плавно меняет цвет, кнопка «+» выпрыгивает при появлении, уведомление выезжает снизу, блоки главной появляются каскадом, числа отсчитываются, полоски плана и кольцо в профиле заполняются, вместо надписи «Загружаем…» мерцающие скелетоны.

**Скорость:**
- Запросы каждого экрана уходят одновременно (главная, план дня, форма продажи, команда, профиль): ждём самый медленный, а не сумму всех.
- Главная сразу показывает последние сохранённые ответы, свежие данные заменяют их (`offline/ReadCache`).
- Выпуск собирается с R8 (сжатие кода и ресурсов, оптимизация) и подписывается тем же ключом, что Capacitor-приложение: `./gradlew :androidApp:assembleRelease`, файл `androidApp/build/outputs/apk/release/androidApp-release.apk`. Для замеров на телефоне, где стоит приложение из магазина, есть сборка `assemblePerf` (те же оптимизации, отдельный идентификатор `.perf`, отладочный ключ). Правила R8 — `androidApp/proguard-rules.pro` (сериализация, Ktor, AndroidSVG).
- Замеры на телефоне (Xiaomi 25062RN2DY): размер 21 МБ (отладочная) → 2,1 МБ (выпускная); холодный запуск ~1,45 с → ~0,41 с; за прогон по всем вкладкам и прокрутке 0,6% «рваных» кадров, медиана кадра 12 мс.

## Сборка и запуск

Нужны JDK 17 (для `androidApp` и `desktopApp`), Android SDK (платформа 35, build-tools) и `native/local.properties` с `sdk.dir` (файл в `.gitignore`).

```bash
cd native
./gradlew :androidApp:assembleDebug          # androidApp/build/outputs/apk/debug/androidApp-debug.apk
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

Клиент для Windows и `shared` собираются и тестируются так же, как раньше (`./gradlew :shared:jvmTest :desktopApp:test`).

## Что проверено и что нет

Проверено на телефоне с живыми данными (Xiaomi 25062RN2DY, MTN_NX1, Android, через `adb`): вход, главная, форма продажи, все вкладки, «Инструменты», отчёты, аналитика, Command Center, задачи, алерты, касса, поддержка, супервайзер, Admin Center, чат с получением вложения. Экраны, которые пишут в боевую систему (отправка продажи и сообщений, открытие и закрытие смены, правка графика, смена ролей, «Удалить», сохранение кассы), на живом сервере не нажимались; их код повторяет проверенный десктопный клиент.

### Баг, найденный и исправленный в этой сессии: кнопка «Назад» закрывала всё приложение

- **Как воспроизводился**: вкладка «Команда» → открыть выпадающий список «Дилер» → нажать аппаратную/системную кнопку «Назад» → закрывалось не выпадающее меню, а всё приложение целиком (сворачивалось на главный экран Android).
- **Причина**: `PickerField`/`DropdownField` (`Compat.kt`, `AddSaleSheet.kt`) не перехватывали системный Back — нажатие проваливалось до `Activity.finish()`. Тот же паттерн (`BackHandler`) уже был в `BottomSheet`, но не был скопирован в эти два компонента при их написании.
- **Исправление**: `BackHandler(enabled = open) { open = false }` в обоих местах.
- **Как подтверждали, что действительно исправлено** (не просто «должно работать по коду»): открыли «Дилер» на «Команде», нажали Back, сделали снимок экрана — список закрылся, приложение осталось на вкладке «Команда»; дополнительно проверили `adb shell dumpsys window | grep mFocusedApp` сразу после нажатия — фокус остался на `com.t2sales.android.native/ru.t2sales.android.MainActivity`, то есть Activity не завершилась и не ушла в фон.

Офлайн-очередь проверена только сборкой: реальный обрыв связи с отправкой продажи не прогонялся.

- Отдельные проверки для сотрудников без связи: кэш чтения (последние данные без сети) подключён у Главной и экрана «Повтор месяца».
- Push-уведомления, быстрая продажа из шторки, виджеты.
