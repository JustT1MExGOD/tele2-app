# Обновление нативного приложения (PC)

[Каталог документации](../../docs/README.md) · [Нативное приложение](../README.md)

Нативное приложение (Compose Desktop) обновляется тем же способом, что и Electron-версия: манифест с отдельного HTTPS-сервера, проверка установщика перед запуском. В отличие от Electron, при запуске приложения обновление ставится **сразу**, как в Discord (см. «Запуск со сплэшем»). Код — `desktopApp/src/main/kotlin/ru/t2sales/desktop/update/`, тесты — `desktopApp/src/test/.../update/UpdaterTest.kt`.

Версия нативного приложения ведётся **отдельно** от веба и бэкенда: единственный источник — `appVersion` в `desktopApp/build.gradle.kts`. Из неё берутся и версия установщика, и версия, которую приложение показывает и сравнивает с манифестом.

## Что делает клиент

| Шаг | Поведение |
| --- | --- |
| Когда проверяет | При каждом запуске (на сплэше, до открытия клиента); дальше первый раз через ~15 с, затем каждые 4 часа; вручную — «О приложении → Проверить обновления» |
| Где | `https://updates.vincere-mortem.ru` (тот же сервер, что у Electron). Переопределяется `T2_UPDATE_BASE_URL` |
| Канал | `stable` (по умолчанию) или `beta` — `T2_UPDATE_CHANNEL` |
| Разработка | Запуск `gradle run` (не установленное приложение) сам ничего не проверяет; включается только явным `T2_UPDATE_BASE_URL` |
| Манифест | Строгая проверка: канал, схема, https, origin, путь `/native/releases/`, имя файла, SHA-256, размер ≤ 500 МиБ |
| Загрузка | Потоком во временный файл, без редиректов, лимит размера во время загрузки, SHA-256 + точный размер, только потом переименование |
| Перед запуском | Повторная проверка размера, SHA-256 и подписи (файл мог быть подменён, пока пользователь думал) |
| Подпись | Authenticode через PowerShell. Политика `warn`: **без подписи — можно** (с предупреждением), **повреждённая или недействительная — блокируется** |
| Установка | При запуске - сразу (сплэш сам скачивает, проверяет и запускает установщик). Обновление, найденное, пока приложение уже работает, - по кнопке «Установить сейчас». В обоих случаях установщик стартует с ключом `/UPDATE` (см. ниже); приложение закрывается через ~1,5 с |
| «Ещё ничего не опубликовано» | Ответ 404 на манифест — это «обновлений нет», а не ошибка |
| Журнал | `%LOCALAPPDATA%\T2 Sales Native\logs\updater.log` (только этапы и категории, без путей, адресов и учётных данных) |
| Кэш загрузок | `%LOCALAPPDATA%\T2 Sales Native\updates\` |

## Запуск со сплэшем

Код: `ui/boot/BootSequence.kt` (последовательность) и `ui/boot/SplashScreen.kt` (окно). Приложение открывается маленьким безрамочным окном, и только потом - клиентом:

1. **Проверяем соединение** - выбор канала DIRECT / RELAY (как раньше делал `AppRoot`), не дольше 12 с.
2. **Ищем обновления** - манифест, не дольше 12 с. Без настроенного сервера (запуск `gradle run`) этап пропускается.
3. Если есть новая версия: **Загружаем** (с процентами и МБ) → **Проверяем подлинность** (SHA-256, размер, подпись по политике) → **Устанавливаем**. Установщик закрывает приложение сам и после установки запускает новую версию, которая снова проходит сплэш.
4. **Входим в аккаунт** - проверка сохранённой сессии (`/me`). Нет сессии - клиент откроется на экране входа.
5. Клиент появляется плавным проявлением; сплэш показывается не меньше ~2 с, чтобы не мигать.

**Запуск никогда не блокируется проблемой обновления.** Недоступный сервер, ошибка загрузки, битая сумма или недействительная подпись - сплэш на 1,6 с пишет «Не удалось обновиться - запускаем текущую версию» и открывает установленную версию. Все проверки безопасности (только https, точный origin, без редиректов, SHA-256, повторная проверка перед запуском) остались прежними; сплэш их не обходит, только убрал ожидание клика.

### Ключ установщика `/UPDATE`

Приложение запускает установщик как `T2SalesNative-Setup-x64-X.Y.Z.exe /UPDATE` (константа в коде, из манифеста в командную строку ничего не попадает). Это не тихая установка: окно с анимацией показывается, но **без страницы приветствия** - установка стартует сразу, после неё новая версия запускается сама и окно закрывается. Ручной запуск установщика двойным щелчком работает как раньше (приветствие, кнопки, «Готово»). Тихий режим `/S` не изменился.

### Просмотр сплэша без сервера

`T2_BOOT_DEMO=update ./gradlew :desktopApp:run` - весь путь с фальшивой загрузкой обновления 1.0.1 (ничего не скачивается и не ставится). Работает только в обычном запуске из исходников, в установленном приложении переменная игнорируется.

`mandatory: true` показывает отметку «ВАЖНОЕ ОБНОВЛЕНИЕ», но не форсирует установку.

## Размещение на сервере

У нативного приложения **свой подкаталог `native/`**, чтобы не пересекаться с Electron-клиентами на том же сервере (у них манифест лежит в `/stable/`, `/beta/`, установщики в `/releases/`):

| Путь на сервере | Содержимое |
| --- | --- |
| `native/stable/manifest.json` | Манифест стабильного канала |
| `native/beta/manifest.json` | Манифест тестового канала |
| `native/releases/` | Неизменяемые установщики `T2SalesNative-Setup-x64-X.Y.Z.exe` |

В Caddy заголовки для существующих правил `/*/manifest.json` и `/releases/*` могут не покрывать вложенный `native/`. Добавьте явно:

```caddyfile
    header /native/*/manifest.json Content-Type "application/json"
    header /native/*/manifest.json Cache-Control "no-cache"
    header /native/releases/* Content-Type "application/octet-stream"
    header /native/releases/* Cache-Control "public, max-age=31536000, immutable"
```

Электрон-клиенты `native/` не запрашивают, нативный клиент не запрашивает `/stable/` и `/releases/`.

## Как выпустить новую версию

1. Поднимите `appVersion` в `desktopApp/build.gradle.kts` (например `1.0.0` → `1.0.1`). Новую версию клиент считает обновлением, только если она **строго больше** установленной.
2. Соберите установщик (без прав администратора, ничего доустанавливать не нужно):

   ```bash
   cd native
   ./gradlew :desktopApp:packageSetup
   ```

   Результат: `desktopApp/build/installer/T2SalesNative-Setup-x64-1.0.1.exe` — уже с именем, которое ждёт клиент обновлений. Устройство и дизайн установщика — в `installer/README.md`.

   Установщик ставит в `%LOCALAPPDATA%\Programs\T2 Sales Native`, создаёт ярлыки на рабочем столе и в «Пуске», запись в «Программах и компонентах» и `Uninstall.exe`. Тихий режим `/S` работает и для установки, и для удаления. При установке поверх закрывает запущенную копию и заменяет только свои папки `app` и `runtime`. Удаление стирает только свои файлы поимённо и никогда не сносит папку целиком.

   *Почему не MSI от jpackage (`packageMsi`/`packageExe`):* на целевом ПК он падал с ошибками Windows Installer 2503/2502 при обычном запуске, а при удалении jpackage-MSI стирает весь каталог установки — так была потеряна соседняя Electron-установка. Эти задачи оставлены в Gradle, но для выпуска не используются.
3. Подготовьте манифест и раскладку (скрипт ничего не публикует):

   ```bash
   node scripts/update-prepare.mjs --channel beta \
     --installer "desktopApp/build/installer/T2SalesNative-Setup-x64-1.0.1.exe" \
     --notes "Что нового" [--mandatory] [--min-supported 1.0.0]
   ```

   Он посчитает SHA-256 и размер и создаст в `update-staging/`:
   `native/beta/manifest.json` и `native/releases/T2SalesNative-Setup-x64-1.0.1.exe` (имя без пробелов — именно такую форму клиент разрешает запускать).
4. Публикация — отдельное согласованное действие оператора:
   1. Скопировать установщик в `native/releases/`, **не перезаписывая** старые версии.
   2. Проверить, что он скачивается по итоговому HTTPS-адресу, а размер и хеш совпадают.
   3. Загрузить манифест под временным именем и атомарно заменить `native/<канал>/manifest.json`.
   4. Проверить на тестовом клиенте: проверка, загрузка, установка.
5. Продвижение `beta → stable` — тот же проверенный установщик и манифест с `--channel stable`.

Установщик обновляет установленную копию «на месте» благодаря постоянному `upgradeUuid` в настройках сборки — его менять нельзя.

**Имя продукта.** Приложение называется `T2 Sales Native` (своя папка, ярлыки, запись в «Программах»), потому что Electron-версия — `T2 Sales`: общие имена и папка портят друг друга. Внутри окна заголовок остаётся «T2 Sales».

## Откат и диагностика

Клиент принимает только более новую версию. Возврат манифеста к старой версии останавливает распространение, но не понижает уже установленную. Основной путь восстановления — новый исправляющий выпуск. Храните несколько прошлых установщиков.

| Симптом | Что проверить |
| --- | --- |
| Новая версия не видна | Канал, что версия числово больше, кэш манифеста, доступность адреса |
| Манифест отклонён | Канал, origin, путь `/native/releases/`, формат имени и версии |
| «Ещё ничего не опубликовано» | Манифеста нет на сервере (404) — это нормально до первого выпуска |
| Загрузка с ошибкой | TLS, перенаправления, размер, SHA-256 |
| Установка запрещена | `updater.log`, повторная проверка, подпись |

## Подпись

Сертификата для подписи сейчас нет, поэтому оба канала работают с политикой `warn`. Когда он появится, в `AUTHENTICODE_POLICY` (`UpdateSecurity.kt`) достаточно переключить `stable` на `Required`.

## Что проверено

| Что | Статус |
| --- | --- |
| Манифест, загрузка, размер и SHA-256, политика подписи (в том числе настоящий PowerShell), запуск установщика, скрипт `update-prepare.mjs` | Тесты `UpdaterTest.kt` проходят; сквозной тест поднимает локальный HTTPS-сервер |
| Все этапы сплэша (соединение, поиск, загрузка с процентами, проверка, установка, вход, передача клиенту) | Проверено на Windows в демо-режиме `T2_BOOT_DEMO=update` |
| Сплэш в обычном запуске из исходников (без сервера обновлений) | Проверено на Windows |
| Режим установщика `/UPDATE` | Проверено на Windows в демо-режиме установщика (`/demo /demo-update /UPDATE`): сразу прогресс, без приветствия, окно закрывается само |
| Полный путь «сервер → загрузка → установщик `/UPDATE` → перезапуск на новой версии» на настоящем сервере | Не проверялось. Для проверки нужен опубликованный установщик более новой версии в канале `beta` |
