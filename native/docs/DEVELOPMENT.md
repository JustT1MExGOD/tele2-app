## Что нужно

| Что | Зачем |
| --- | --- |
| JDK 17 | Сборка и запуск; упаковка `jpackage`. Другие версии не проверялись |
| Windows 10/11 x64 | Установщик собирается штатным `csc.exe` из `C:\Windows\Microsoft.NET\Framework64\v4.0.30319` с WPF; отдельного .NET SDK не нужно |
| Доступ к серверу | Приложение работает с рабочим сервером; тестовой копии в репозитории нет |

Gradle не нужно ставить: есть `gradlew` (Gradle 8.10.2 из `gradle/wrapper`).

## Команды

Рабочий каталог — `native/`. В Git Bash перед вызовом Gradle задайте JDK; в PowerShell — `$env:JAVA_HOME` и `$env:Path`.

```bash
export JAVA_HOME="/c/Users/<пользователь>/tools/jdk-17.0.20.1+1"   # пример пути
export PATH="$JAVA_HOME/bin:$PATH"
```

| Задача | Команда |
| --- | --- |
| Запустить из исходников | `./gradlew :desktopApp:run` |
| Проверить, что всё собирается | `./gradlew :desktopApp:compileKotlin` |
| Тесты общего слоя (сериализация ответов) | `./gradlew :shared:jvmTest` |
| Тесты обновлений | `./gradlew :desktopApp:test` |
| Собрать установщик | `./gradlew :desktopApp:packageSetup` |
| Только образ приложения (без установщика) | `./gradlew :desktopApp:createDistributable` |
| Только заглушку установщика | `./gradlew :desktopApp:compileSetupStub` |

Результат `packageSetup`: `desktopApp/build/installer/T2SalesNative-Setup-x64-<версия>.exe` (около 100 МБ; внутри — приложение вместе с урезанной средой Java). Имя файла уже такое, какое ждёт клиент обновлений.

`build/` и `.gradle/` не попадают в git (см. `native/.gitignore`).

## Переменные окружения

Все необязательны. Работают и при запуске из исходников, и в установленном приложении, если не сказано иначе.

| Переменная | Значение | Действие |
| --- | --- | --- |
| `T2_NETWORK_MODE` | `auto`, `direct_only`, `relay` | Режим сети при запуске (перекрывает выбор в панели) |
| `T2_RELAY_URL` | https-адрес | Другой ретранслятор; http допустим только на loopback |
| `T2_UPDATE_BASE_URL` | https-адрес | Включает проверку обновлений при запуске из исходников и меняет сервер обновлений |
| `T2_UPDATE_CHANNEL` | `stable` (по умолчанию), `beta` | Канал обновлений |
| `--tray` (аргумент запуска) | | Запуск скрыто, в трее (так запускает автозапуск Windows). Без сплэша; окно вызывается из значка или повторным запуском; Ctrl+Alt+P открывает мини-окно быстрой продажи |
| `T2_PACE_HOUR` | число, например `14.5` | **Только запуск из исходников.** Подменяет московское время для виджета «Темп дня» (14.5 = 14:30), чтобы посмотреть дневное состояние ночью |
| `T2_SHIFT_RESULT_DEMO` | `1` | **Только запуск из исходников.** При старте показывает карточку итога смены с примерными числами; на сервер ничего не отправляется |
| `T2_OUTBOX_DEMO` | `1` | **Только запуск из исходников.** Кладёт в очередь две демо-записи со статусом «проверить» (они никогда не отправляются на сервер), чтобы посмотреть индикатор и список. Удаляются кнопкой «Удалить» |
| `T2_BOOT_DEMO` | `update` | **Только запуск из исходников.** Показывает весь путь сплэша с фальшивой загрузкой обновления 1.0.1 — ничего не скачивается и не ставится. В установленном приложении игнорируется |

Пример просмотра сплэша:

```powershell
$env:T2_BOOT_DEMO = "update"
./gradlew :desktopApp:run
```

Режимы установщика (запуск собранной заглушки `desktopApp/build/setup/stub.exe`):

| Аргументы | Что показывает |
| --- | --- |
| `/demo` | Мастер установки с поддельным движком, ничего не трогает |
| `/demo /demo-update` | То же для обновления поверх версии 1.0.0 |
| `/demo /demo-update /UPDATE` | Режим автообновления: сразу прогресс, без приветствия |
| `/demo-uninstall` | Мастер удаления |

## Проверка интерфейса

Автоматических тестов интерфейса нет. Экраны проверяются вручную по снимкам настоящего окна. Правила, выученные на практике:

1. **Убить старые копии перед запуском.** Остановка Gradle не останавливает саму JVM: старые окна накапливаются. Перед перезапуском остановите процессы `java.exe`, в командной строке которых есть `ru.t2sales.desktop.MainKt`.
2. **Вынести окно вперёд.** Окно, запущенное из скрытого скрипта, открывается позади редактора, и снимок или ввод попадают не туда. Перед снимком вызовите `(New-Object -ComObject WScript.Shell).AppActivate($pid)`, а дескриптор окна берите заново перед каждым снимком (при смене сплэша на клиент он меняется). Одного `SetForegroundWindow` недостаточно.
3. **Снимок** — `CopyFromScreen` по прямоугольнику окна из `GetWindowRect` при включённом `SetProcessDPIAware`, иначе размеры будут неверными на экране с масштабом.
4. **Клавиши.** Стрелки через `keybd_event` нужно отправлять с флагом расширенной клавиши (1), иначе они приходят как клавиши цифровой клавиатуры. Символы вводятся по раскладке: латинские коды дадут кириллицу в русской раскладке.
5. **Случайные клики** меняют состояние приложения. Тема хранится в реестре; если проверка её переключила, верните обратно.
6. **Проверять, что правка попала в файл.** Тихий сбой скриптовой замены давал «собирается, но кнопки нет».

## Соглашения по коду

- **Экраны переносятся с веба один в один.** Перед переносом читают разметку, стили, модуль страницы и API; переносят каждый раздел и кнопку. Упрощённые версии не выпускаются; пропуски называют заранее.
- **Ответы сервера** — типы в `ApiTypes.kt` с именами полей как в `backend/src/shared/api-types.ts`, без преобразования регистра. Для нестабильных ответов используется `JsonObject` и помощники `obj()`, `arr()`, `dbl()`, `str()` (пакет `ui/analytics`).
- **Движение** — только через `ui/components/Motion.kt`, чтобы длительности и кривая были едиными. Анимация играет один раз при появлении и не задерживает работу.
- **Выпадающие списки** — только `DropdownField` и `PopoverPanel`; стандартный `DropdownMenu` не используется.
- **Оформление** — цвета и отступы только из `T2Colors`, `T2Radius`, `T2Spacing`. Сплэш — единственное исключение: у него собственная фиксированная тёмная палитра.
- **Комментарии** — краткие, по-английски, только там, где причина не очевидна.
- **Установщик** — C# 5: без `$""`, `?.`, членов-выражений.

## Выпуск версии

Версия нативного клиента не связана с версиями веба и backend, их файлы (`backend/package.json`, `changelog.ts`, бейдж в корневом `README.md`) не трогаются.

1. Поднимите `appVersion` в `desktopApp/build.gradle.kts` (новая версия считается обновлением, только если она строго больше установленной).
2. Добавьте запись в [CHANGELOG.md](../CHANGELOG.md).
3. `./gradlew :shared:jvmTest :desktopApp:test :desktopApp:packageSetup`.
4. Для раздачи через сервер обновлений — [UPDATES.md](UPDATES.md#как-выпустить-новую-версию): манифест и папка публикации готовятся `scripts/update-prepare.mjs`. Публикация на сервер — внешнее действие, выполняется отдельно и только осознанно.

Раздача файла напрямую (без сервера обновлений): отправьте `T2SalesNative-Setup-x64-<версия>.exe`; установка — двойным щелчком, права администратора не нужны, Windows SmartScreen может предупредить, так как файл не подписан.

## Частые проблемы

| Симптом | Причина и действие |
| --- | --- |
| Сборка падает на `csc.exe` или WPF | Нет .NET Framework 4 x64 в `C:\Windows\Microsoft.NET\Framework64\v4.0.30319` или папки `WPF` внутри неё |
| В упакованном приложении вылет, из исходников всё работает | В урезанной среде Java нет модуля. Список модулей — `modules(...)` в `desktopApp/build.gradle.kts` |
| Не открывается окно после правок | Осталась старая копия JVM: остановите её (см. [проверку интерфейса](#проверка-интерфейса)) |
| Приложение просит войти после каждого запуска | Проверьте `%USERPROFILE%\.t2sales\cookies.json`: файл должен обновляться |
| Обновление не находится | Из исходников проверка выключена, пока не задан `T2_UPDATE_BASE_URL`; в установленном — смотрите `%LOCALAPPDATA%\T2 Sales Native\logs\updater.log` |
