# T2 Sales — рабочее соглашение с Claude Code

## Что можно делать без подтверждения

Ниже — заранее одобренный владельцем проекта объём действий. Действует только
пока соблюдается обычная для этого репозитория дисциплина (тесты зелёные,
`tsc --noEmit` чистый, версия/changelog обновлены по конвенции ниже).

- `git add` (явный список файлов, никогда `-A`/`.`), `git commit`, `git push` в `main`.
- Read-only запросы к продовой базе через Railway-прокси (`DATABASE_URL` из
  `backend/.env.test`) — только для расследования, без INSERT/UPDATE/DELETE/DDL.
- Прогон системы миграций локально/в CI. На проде миграции применяются
  автоматически при старте сервера после деплоя — это уже покрыто пунктом
  про `git push`, отдельно накатывать руками не нужно.
- `railway logs`, `railway status`, `curl .../health` и другие read-only
  проверки задеплоенного сервиса.
- Поднятие/остановка одноразового локального Postgres для прогона тестов.
- Реальные отправки в Telegram-чат при локальном тестировании — если бот
  случайно послал сообщение во время тестов, это не инцидент, специально
  разбираться не нужно.

## Что по-прежнему требует явного подтверждения

- Любая запись (INSERT/UPDATE/DELETE/DDL) напрямую в продовую базу в обход
  обычной системы миграций.
- `git push --force`, `git reset --hard`, удаление веток и любые другие
  деструктивные/необратимые git-операции.
- Изменение конфигурации Railway-сервиса, переменных окружения, скейлинга.
- Всё, что не попадает в список выше и имеет эффект за пределами этого
  репозитория.

## Конвенции версионирования

- MAJOR = эпоха, MINOR = эпик/фича (с changelog-записью и анонсом в
  Telegram-чат), PATCH = хотфикс/рефакторинг без changelog.
- Перед пушем: типизация (`npx tsc --noEmit`), `npm run smoke:frontend`,
  полный прогон `npx vitest run` на одноразовом локальном Postgres.
- Версия/changelog обновляются в `backend/package.json`,
  `backend/src/changelog.ts`, `README.md` (бейдж + строка версии + таблица
  истории версий).
