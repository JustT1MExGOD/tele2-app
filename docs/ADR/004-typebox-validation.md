# 004 — TypeBox для валидации write-роутов

**Статус**: принято, реализовано (19.18.0→19.21.0, весь write-API).

## Контекст

`request.body as any` по всему write-API — валидация тела запроса (если
вообще была) размазана по ручным `if`-проверкам внутри каждого
обработчика, непоследовательно, легко пропустить поле.

## Решение

`@sinclair/typebox` схемы на `schema.body` каждого write-роута. Fastify
валидирует запрос встроенным ajv-компилятором ДО того, как управление
доходит до обработчика — невалидный запрос никогда не видит бизнес-логику.
Отгружено 4 заходами (по группам роутов, не всё разом) — денежные/
расписательные write-роуты → доступ/роли/CRUD → задачи/поддержка/
промокоды/объявления → алерты/what-if/метрики/планы/отчёты/бренд.

## Альтернативы

- **Zod** — не рассматривался всерьёз: Fastify нативно компилирует
  JSON Schema (через ajv) на старте для скорости; TypeBox — тонкая
  типобезопасная обёртка ровно над JSON Schema, без рантайм-моста между
  двумя разными системами валидации.
- **Ручная валидация** (статус-кво) — отклонено по причине, которая и
  вызвала эту работу: непоследовательность, `any`-типизированные тела,
  реальные пропущенные проверки.

## Последствия

- **Найденная ловушка ajv-коэрсии `null`** (19.19.0) — `coerceTypes: true`
  (Fastify-дефолт) молча превращает `null` в `0`/`""` для полей, которые
  фронтенд шлёт как `null` намеренно (геолокация при отказе в доступе,
  сброс кастомного названия). Фикс — `Type.Union([Type.Null(), ...])` **с
  Null первым** в объединении (ajv коэрсит на первом подходящем варианте
  по порядку). Урок закреплён как конвенция: новое поле, которое фронтенд
  может прислать `null` намеренно, обязано использовать этот порядок.
- Динамические по форме тела (кастомные метрики, `sync/batch`/`what-if
  moves`) сознательно оставлены `additionalProperties: true` — схема не
  должна быть строже уже отлаженной ручной логики внутри обработчика.
- Побочный эффект по ходу переноса: два BFQ-роута и один reachability-баг
  (`code_required` в промокодах, недостижимый из-за схемы) найдены не
  специально, а как естественный результат более внимательного прохода по
  каждому write-роуту.
