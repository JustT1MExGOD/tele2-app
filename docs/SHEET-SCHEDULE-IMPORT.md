## Принцип: приложение приоритетнее таблицы

Каждая строка графика (`schedules`) несёт `source: 'manual' | 'sheet_import'`.

- Правка через приложение (`POST /schedules`, `/schedules/bulk`) всегда
  ставит `source='manual'` — даже если строка раньше пришла из таблицы.
- Импорт из таблицы (`upsertFromSheet` в
  `backend/src/data/repositories/schedules.ts`) обновляет строку, только
  если её `source` всё ещё `'sheet_import'`. Если строку уже поправили
  руками — импорт молча её не трогает.

Это значит: таблица — источник для *первого* внесения графика; как
только кто-то поправил конкретный день конкретного сотрудника внутри
приложения, эта ячейка перестаёт слушать таблицу насовсем (пока её не
удалят).

## Сопоставление сотрудника

Таблица знает сотрудника только по написанному имени (`ФИО`). Сопоставление
с `employees.id` (`backend/src/core/integrations/sheet-name-match.ts`):

1. Уже подтверждённое соответствие (`sheet_schedule_mappings`) — применяется сразу.
2. Точное совпадение имени (без учёта регистра/пробелов/ё-е) — подтверждается
   автоматически, дальше ведёт себя как п.1.
3. Похожее, но не точное имя (опечатка) — строка уходит в очередь
   **Admin Center → «Импорт графика из Таблиц»** и ничего не пишет в
   график, пока админ не подтвердит, кто это.
4. Совсем не похоже ни на кого — тоже в очередь, без предложенного кандидата.

## Формат ячейки

| Значение | Смысл |
| --- | --- |
| `10-22`, `9-21` | смена с такими часами (конец раньше начала = смена через полночь) |
| `вых`, `выходной`, `отп`, `отпуск`, пусто | выходной — импорт удаляет смену на этот день, если она раньше тоже пришла из таблицы |
| что угодно другое | не разобрано, строка пропускается (в лог, не в очередь подтверждения — это не про сотрудника, а про формат ячейки) |

Часы **всегда** пересчитываются из времени смены (`10-22` → 12ч), а не
берутся из числа, вписанного во вторую строку пары сотрудника — вписанные
часы могут расходиться с реальным временем (учёт перерыва и т.п.), и это
осознанный выбор: правильным считается время смены. Edit по второй
(часовой) строке пары сам по себе безвреден — её значение (голое число)
не проходит формат `HH-HH`/выходного, `parseShiftCell` вернёт «не
разобрано», строка тихо пропускается.

## Точки продаж — по цвету ячейки

Одна таблица покрывает несколько точек сразу — какая именно, определяется
**цветом заливки** отредактированной ячейки (не текстом, не отдельной
колонкой). Цвет → `store_id` — таблица соответствий целиком в константе
`COLOR_TO_STORE` скрипта; правится один раз при установке, под цвета
конкретной таблицы.

`'__REPLACEMENT__'` — специальное значение для цвета «Замена» (когда
известно, что сотрудник работает подмену, но не в какой конкретно точке
пока) — то же самое значение, что и `REPLACEMENT_PLACEHOLDER_STORE_ID`
(`backend/src/shared/replacement.ts`), которым пользуется сама форма
графика в приложении для той же ситуации.

Ячейка нейтрального/незнакомого цвета (например, белая ячейка выходного)
шлётся с пустым `store_id` — для выходного это не проблема (удаление
смены не завязано на точку), а для настоящей смены с нераспознанным
цветом импорт просто пропускает строку (`skipped_no_store`) — ничего не
пишет в график с несуществующей точкой.

## Настройка на стороне сервера

Один обязательный секрет, задаётся в окружении сервера (Railway):

```
SHEETS_WEBHOOK_SECRET=<длинная случайная строка>
```

Без него эндпоинт `POST /integrations/sheets/schedule-webhook` отвечает
`503` и ничего не принимает — фича не активна, пока секрет не задан.
Сгенерировать: `openssl rand -hex 32` (или любой другой источник
случайности, главное — не короткая фраза).

## Настройка Apps Script в самой таблице

В Google Таблице: **Расширения → Apps Script**, вставить триггер
`onEdit` и настроить константы под конкретную таблицу/сеть. Реальная
раскладка этой таблицы: строка = дата в шапке (`HEADER_ROW`), колонка A —
ФИО, **смёрджена на пару строк одного сотрудника** (строка времени смены
+ строка часов под ней) — поэтому имя читается через якорь мёрджа
(`getEmployeeName_`), а не напрямую из отредактированной строки: для
нижней (часовой) строки пары прямое чтение колонки A вернуло бы пустоту.

Месяц берётся не из константы, а из **имени листа** — формат «Месяц Год»
(`Сентябрь 2026`, `Октябрь 2026`, ...): один и тот же скрипт, вставленный
один раз на всю таблицу, работает и для уже существующих листов, и для
новых, которые появятся по мере добавления следующих месяцев — их имя
просто должно следовать тому же формату.

Цвета и `store_id` этой конкретной таблицы уже известны и вписаны в код
ниже:

| Цвет | Точка | `store_id` |
| --- | --- | --- |
| `#ff6d01` (оранжевый) | Калинина 2 | `kalinina2` |
| `#ffd966` (жёлтый) | Калинина 11 | `kalinina11` |
| `#6d9eeb` (голубой) | Космонавтов 20а | `kosmonavtov` |
| `#00ff00` (зелёный) | Замена (без точки) | `__REPLACEMENT__` |

Если добавится ещё одна точка/цвет — новую пару добавить в
`COLOR_TO_STORE` тем же способом: выделить ячейку этого цвета, выполнить
`SpreadsheetApp.getActiveRange().getBackground()` через временную функцию
с `Logger.log(...)`, посмотреть результат в **View → Executions**, и
взять `store_id` из `/admin/stores` в Admin Center.

```javascript
// Настройки конкретной таблицы.
const WEBHOOK_URL = 'https://<ваш-сервер>/integrations/sheets/schedule-webhook';
const WEBHOOK_SECRET = '<тот же SHEETS_WEBHOOK_SECRET, что на сервере>';
const ORG_ID = 'default';        // как в вашей системе org_id, обычно 'default'
const NAME_COLUMN = 1;           // колонка A — ФИО (смёрджена на пару строк сотрудника)
const HEADER_ROW = 1;            // строка с датами

// Цвет ячейки -> store_id. '__REPLACEMENT__' — спец-значение для "Замена"
// (без конкретной точки), то же самое, что REPLACEMENT_PLACEHOLDER_STORE_ID
// на стороне сервера.
const COLOR_TO_STORE = {
  '#ff6d01': '<store_id Калинина 2>',
  '#ffd966': '<store_id Калинина 11>',
  '#6d9eeb': '<store_id Космонавтов 20а>',
  '#00ff00': '__REPLACEMENT__'   // замена
};

const MONTH_NAMES = {
  'январь': '01', 'февраль': '02', 'март': '03', 'апрель': '04',
  'май': '05', 'июнь': '06', 'июль': '07', 'август': '08',
  'сентябрь': '09', 'октябрь': '10', 'ноябрь': '11', 'декабрь': '12'
};

function parseMonthFromSheetName(name) {
  const m = name.trim().toLowerCase().match(/^([а-яё]+)\s+(\d{4})$/);
  if (!m) return null;
  const monthNum = MONTH_NAMES[m[1]];
  return monthNum ? `${m[2]}-${monthNum}` : null;
}

// Колонка A смёрджена на обе строки пары сотрудника — getValue() на
// "нижней" (часовой) строке сам по себе пуст, читаем реальный якорь мёрджа.
function getEmployeeName_(sheet, row) {
  const cell = sheet.getRange(row, NAME_COLUMN);
  const merged = cell.getMergedRanges();
  const anchor = merged.length ? merged[0].getCell(1, 1) : cell;
  return anchor.getValue().toString().trim();
}

function onEdit(e) {
  const sheet = e.range.getSheet();
  const row = e.range.getRow();
  const col = e.range.getColumn();
  if (row <= HEADER_ROW || col <= NAME_COLUMN) return; // правка не в ячейке графика

  const yearMonth = parseMonthFromSheetName(sheet.getName());
  if (!yearMonth) return; // имя листа не похоже на «Месяц Год» — не трогаем

  const employeeName = getEmployeeName_(sheet, row);
  const day = sheet.getRange(HEADER_ROW, col).getValue();
  if (!employeeName || !day) return;

  const dayNum = Number(day);
  if (!dayNum || dayNum < 1 || dayNum > 31) return;
  const workDate = `${yearMonth}-${String(dayNum).padStart(2, '0')}`;
  const shiftRaw = e.range.getValue().toString().trim();
  const storeId = COLOR_TO_STORE[e.range.getBackground()] || '';

  const payload = {
    org_id: ORG_ID,
    store_id: storeId,
    employee_name: employeeName,
    work_date: workDate,
    shift_raw: shiftRaw
  };

  UrlFetchApp.fetch(WEBHOOK_URL, {
    method: 'post',
    contentType: 'application/json',
    headers: { 'X-Sheets-Webhook-Secret': WEBHOOK_SECRET },
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  });
}
```

`onEdit` встроенные триггеры Google Sheets не могут делать авторизованные
внешние вызовы в некоторых аккаунтах (Workspace-ограничения) — если
`UrlFetchApp.fetch` падает с ошибкой прав, замените простой триггер на
установленный (**Триггеры → Добавить триггер → onEdit → Из таблицы →
При редактировании**), это даст те же права, что у обычного скрипта.

## Проверка

1. Впишите в таблице смену новому/тестовому сотруднику, чьего имени точно
   нет в системе — она должна появиться в Admin Center → «Импорт графика
   из Таблиц» как ожидающая подтверждения.
2. Впишите смену сотруднику, чьё ФИО в таблице совпадает с `employees.full_name`
   один-в-один — она должна сразу появиться в графике приложения.
3. Поправьте эту же смену внутри приложения, затем измените ту же ячейку
   в таблице ещё раз — график **не должен** измениться (защита `source='manual'`).

## Известные ограничения

- Точка определяется по **точному** совпадению hex-кода фона ячейки —
  если кто-то закрасит смену цветом, которого нет в `COLOR_TO_STORE`
  (даже близким по оттенку), импорт молча пропустит настоящую смену
  (`skipped_no_store`), ничего не сломав, но и ничего не применив.
- Месяц разбирается из имени листа строго в формате «Месяц Год» (напр.
  `Сентябрь 2026`) — `parseMonthFromSheetName()`. Лист с другим названием
  (например, без года или на английском) молча игнорируется (`onEdit`
  выходит раньше, ничего не отправляя) — переименуйте лист под этот формат.
- Массовая правка (вставка сразу нескольких ячеек, автозаполнение) шлёт
  `onEdit` только для реально изменённых ячеек — Google Sheets это гарантирует,
  но при вставке из буфера обмена может прислать не все ячейки диапазона
  на некоторых аккаунтах. Разовая ручная проверка после большой вставки —
  на усмотрение того, кто ведёт таблицу.
- Нет автотеста, поднимающего реальный Postgres для DB-части (приоритет
  `source`, очередь подтверждения) — покрыты только чистые функции
  сопоставления имени и разбора ячейки (`backend/tests/unit/sheet-schedule-import.test.ts`).
