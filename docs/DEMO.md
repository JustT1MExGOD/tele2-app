# Демо-сценарий

> Актуальный сценарий на смену устаревшему [PRESENTATION.md](./archive/PRESENTATION-v14.md)
> (v14.1, архив). Прод требует подтверждённую identity — подписанную
> Telegram `initData` либо браузерную cookie-сессию (телефон+пароль,
> с 20.35.0), никогда голый заголовок — демо ведётся **живьём через бота**
> (самый наглядный канал для комиссии), не curl'ом с поддельными
> заголовками. Вход с компьютера (без Telegram) — тоже реальный
> рабочий сценарий с 20.37.0, но не основной сценарий этого демо-скрипта.

## Перед демо

- Открывать Mini App **из Telegram-бота** (Menu Button), не из браузера —
  первый заход из браузера ловит экран регистрации без реальной identity.
- Заранее подготовить demo-аккаунты трёх ролей (`employee`, `manager`,
  `admin`) с `access_status='active'` в тестовой/демо-сети — не создавать
  их на глазах у комиссии через реальную заявку (долго, зависит от чужого
  approve).
- Единственная безопасная проверка со стороны без Telegram — публичный
  health-check:
  ```powershell
  Invoke-RestMethod "https://<app>.up.railway.app/health"
  ```
  Всё остальное (роли, данные, продажи) — только живьём через бота с
  подписанным `initData`. Голый `X-Telegram-Id` в проде не пройдёт auth
  (см. [SECURITY.md — аутентификация](./SECURITY.md#2-аутентификация)) —
  не пытаться демонстрировать через него, это не рабочий метод входа.
- Railway: **1 реплика**, без параллельно запущенного локального бота
  (иначе `409 getUpdates` прямо во время демо).

## Сценарий (8-10 мин)

| # | Роль | Что показать | Что это доказывает |
|---|------|---------------|---------------------|
| 1 | — | `GET /health` → `{status:'ok', today: <МСК-дата>}` | Живой прод, время сервера — Москва, не UTC контейнера |
| 2 | employee | Открыть смену (гео + время), внести продажу быстрым текстовым вводом («две симки и один mnp») | NLP-разбор, живой план/факт на экране сразу после ввода |
| 3 | employee | Выключить сеть на телефоне (авиарежим), внести ещё одну продажу | Продажа уходит в офлайн-очередь, не теряется |
| 4 | employee | Включить сеть обратно | Очередь синхронизируется сама, вторая продажа появляется в истории |
| 5 | manager | Command Center на главной | Health-score сети, конкретная просевшая точка, AI-гипотеза причины просадки (Groq) |
| 6 | manager | Кнопка «Создать задачу» прямо из просевшей точки | Замыкает цикл данные → alert → action → task, не просто дашборд |
| 7 | manager | Закрыть смену сотрудника (или показать на своей) | Разбор смены: score, факт/план, чего не хватило до идеальной, XP/уровень/стрик |
| 8 | manager | Live-карта сети | Кто на смене, % плана, статус — по всей сети одним экраном |
| 9 | admin | `GET /audit` (или экран, если подключён) | Каждое чувствительное действие — кто/когда/что было/что стало, не только «что сейчас» |
| 10 | — | Дождаться (или вручную дёрнуть) отправку итогового отчёта в чат сети | PNG-картинка с планом/фактом/фокусом на завтра приходит сама, без копипасты |

## Если что-то пошло не так

| Симптом | Действие |
|---------|----------|
| Mini App не открывается / белый экран | Полностью закрыть и открыть заново из бота (кэш WebView) |
| 403 на Command Center | Аккаунт демо — `senior`, не `manager`/`admin`; `senior` намеренно не видит эту вкладку (см. [SECURITY.md](./SECURITY.md#3-авторизация-rbac)) |
| Задача создана, но карточка не обновилась | Обновить страницу вручную (кнопка reload в шапке) |
| Живая карта/Command Center пустые | В demo-сети нет открытых смен на сегодня — открыть демо-смену заранее, не во время презентации |

Больше сценариев сбоев — [TROUBLESHOOTING.md](./TROUBLESHOOTING.md).

## Чего НЕ показывать

- `ALLOW_INSECURE_AUTH` / `X-Telegram-Id` без initData — dev-фоллбэк,
  не рабочий сценарий для прода, показывать как «вход» — вводить в
  заблуждение.
- SQL-восстановление доступа админу (`docs/RUNBOOK.md`) — операционная
  процедура на крайний случай, не часть продукта.
- Реальный `BOT_TOKEN` в логах/консоли/шеринге экрана.

## Фраза для комиссии

> Это не бот с таблицей — это операционная система смены: единый источник
> истины в Postgres, роли, живая аналитика с AI-объяснением и отчёты без
> копипасты.
