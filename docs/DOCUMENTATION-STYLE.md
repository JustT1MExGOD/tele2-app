## Структура документа

1. Один заголовок первого уровня: предмет документа на русском языке.
2. Короткое введение: для кого документ и какую задачу решает.
3. Ссылка на каталог документации.
4. Оглавление для длинных документов.
5. Тематические разделы второго уровня; подразделы — третьего.
6. Связанные материалы и ограничения, если они нужны для применения инструкции.

Имена файлов, API и переменных сохраняются без перевода. Остальной текст, заголовки, подписи таблиц и пояснения пишутся по-русски. При первом использовании непонятного сокращения дайте расшифровку или ссылку на [словарь](GLOSSARY.md).

## Таблицы, списки и схемы

Таблица подходит для сравнения, перечня настроек и соответствия «симптом → действие». Длинное описание релиза оформляйте отдельным разделом, а не ячейкой на несколько страниц.

Список используйте для шагов или равноправных пунктов. Отделяйте его пустой строкой от окружающего текста. Не заменяйте обычные абзацы длинными вложенными списками.

Mermaid уместен для переходов состояний и потоков между компонентами. Схема должна объяснять одну связь. Избегайте широких цепочек; используйте направление сверху вниз и короткие русские подписи. Не добавляйте HTML-переносы внутрь подписей.

## Команды и примеры

Перед блоком укажите рабочий каталог, оболочку и необходимые настройки. Добавляйте язык блока: `bash`, `powershell`, `json`, `sql`, `typescript` или `text`. Скопированная команда не должна содержать необъяснённых квадратных скобок с необязательными аргументами.

Учебные адреса, хеши и значения явно помечайте как примеры. Не подменяйте реальный результат тестирования вымышленным успешным выводом. Для операций с БД различайте локальную одноразовую базу и рабочую среду.

## Статусы и источники фактов

| Формулировка | Когда применять |
| --- | --- |
| В исходниках | Проверено по конкретному файлу или конфигурации |
| Проверено локально | Известны команда, окружение и фактический результат |
| Проверено на Windows | Пройден соответствующий сценарий на Windows |
| Историческое подтверждение | Сохранён результат предыдущего прохода |
| Запланировано | Решение ещё не реализовано или не принято окончательно |
| Не проверялось | Нет подходящего подтверждения в текущей работе |

Версия пакета не доказывает доступность сервера. Модульный тест не доказывает работу всей системы. Историческая дорожная карта не является обещанием новых сроков.

## Поддержка ссылок и актуальности

При переименовании заголовка обновите входящие ссылки или сохраните старый якорь. Используйте относительные ссылки для файлов репозитория. Новые документы добавляйте в [каталог](README.md), решения — также в [каталог ADR](ADR/README.md).

Историю не переписывают как текущее руководство. Новое поведение описывают в актуальном справочнике, старые результаты сохраняют с обозначением периода. Правила разрешённых действий находятся в [CLAUDE.md](../CLAUDE.md); оформление документации не расширяет их.
