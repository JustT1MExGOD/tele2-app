## Изоляция окна

| Параметр Electron | Значение | Смысл |
| --- | --- | --- |
| `contextIsolation` | `true` | Контексты страницы и preload разделены |
| `nodeIntegration` | `false` | Страница не получает Node.js API |
| `sandbox` | `true` | Процесс отображения работает в песочнице |
| `webSecurity` | `true` | Стандартные ограничения веб-платформы включены |
| `allowRunningInsecureContent` | `false` | Небезопасный активный контент не разрешён |

Решения по транспорту не должны вводить `ignore-certificate-errors`, отключать проверку сертификатов или менять эти параметры. Приложение не содержит серверных ключей или общего секрета, который превращал бы desktop в доверенного клиента.

## Интерфейс между страницей и основным процессом

Контракт находится в `desktop/src/shared/ipc-contract.ts`. Через preload доступны только конкретные операции:

| Группа | Методы |
| --- | --- |
| Сведения | `getVersion`, `getPlatformInfo` |
| Сеть | `getNetworkStatus`, `runNetworkDiagnostics`, `retryDirectConnection`, `setNetworkModePreference`, `onNetworkStatusChanged` |
| Обновления | `checkForUpdates`, `getUpdateStatus`, `downloadUpdate`, `installUpdate`, `onUpdateStatusChanged` |

Нет универсальных методов исполнения команд, чтения файлов, произвольных HTTP-запросов или вызова произвольного IPC-канала. Подписки принимают обработчик события; действия обновления не принимают путь к установщику или командную строку от страницы.

## Навигация и авторизация

Основное окно сохраняет канонический origin приложения. Внешние разрешённые `https:` и `mailto:` ссылки обрабатываются после разбора URL; схемы `javascript:`, `file:`, `data:` и произвольные пользовательские схемы не должны открываться как привилегированная навигация.

Cookie с `HttpOnly` не извлекаются JavaScript-кодом страницы. Сессия desktop не отменяет MFA, WebAuthn, правила Telegram-подтверждения или серверные роли. При проблемах WebAuthn проверяют транспорт и origin; ослаблять серверную проверку нельзя.

## Relay: назначение и ограничения

Relay пересылает запросы только к настроенному upstream. Клиент не выбирает произвольный хост, порт или конечный сервер. Проверка исходящего адреса и DNS ограничивает обращения к внутренним и служебным диапазонам. Метод `CONNECT` не превращает сервис в универсальный туннель.

Тела запросов передаются как двоичные данные. Ограничения размера, времени ожидания, одновременных запросов и частоты обращений дополняют серверные ограничения. Они не заменяют распределённые проверки на стороне backend.

| Данные | Обработка |
| --- | --- |
| `Host`, `Origin` | Формируются для канонического upstream по контракту relay |
| Заголовки запроса и ответа | Передаются по разрешённому списку |
| `Forwarded`, `X-Forwarded-*`, `X-Real-IP`, `Proxy-Authorization` | Не используются как произвольное доверенное утверждение клиента |
| Служебные заголовки соединения | Исключаются или пересчитываются |
| Несколько `Set-Cookie` | Сохраняются раздельно, без некорректного объединения запятой |
| `User-Agent` | Не служит доказательством прав или доверия |

TLS проверяется на соединениях desktop → relay и relay → upstream. Входной HTTP-процесс relay предполагает корректно настроенный доверенный TLS-терминатор. Параметры доверия прокси должны соответствовать реальной схеме размещения.

## Что означает компрометация компонента

| Сценарий | Граница защиты и остаточный риск |
| --- | --- |
| Ошибка или внедрённый код на странице | Изоляция и узкий IPC ограничивают доступ к ОС; сервер всё равно обязан проверять каждую операцию |
| Подмена сетевого трафика | Проверка TLS отклоняет недействительные сертификаты; доверенный локальный корневой сертификат меняет модель доверия |
| Компрометация relay | Оператор с контролем процесса может читать и менять проходящие данные. HTTPS до relay не обеспечивает сквозную недоступность данных этому узлу |
| Компрометация установленного приложения или учётной записи ОС | Нельзя гарантировать защиту пользовательской сессии от самого скомпрометированного окружения |
| Подмена установщика | Проверяются адрес, размер, SHA-256 и Authenticode согласно политике; защита зависит также от доверия к серверу манифестов |
| Произвольная команда через обновление | Контракт не принимает команды и аргументы; запуск разрешён только для проверенного установщика |

Ограничение relay одним upstream описывает штатный код. Оно не ограничивает злоумышленника, полностью управляющего хостом relay.

## Обновления и конфигурация

Обновления реализованы и требуют явного действия пользователя. Старое утверждение «обновления отключены» больше не описывает проект. Проверки запуска и действующая политика подписи подробно разобраны в [DESKTOP-UPDATES.md](DESKTOP-UPDATES.md).

Переменные `T2_*` читаются при запуске процесса; это не исключительно параметры сборки. `WINDOWS_COMPAT` остаётся зарезервированным состоянием без работающего вспомогательного транспорта. Приложение не настраивает системный VPN или глобальный прокси.
