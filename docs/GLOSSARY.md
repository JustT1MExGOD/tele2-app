## Компоненты и интерфейс

| Термин | Значение в проекте |
| --- | --- |
| Backend | Сервер: обработка запросов, бизнес-правила и работа с PostgreSQL |
| Frontend | Веб-интерфейс пользователя |
| Desktop | Приложение Windows на Electron с тем же веб-интерфейсом |
| Relay | Промежуточный сервис пересылки к одному настроенному серверу |
| Mini App | Веб-приложение, открываемое внутри Telegram |
| PWA | Веб-приложение с возможностью установки средствами браузера |
| DIRECT / RELAY / OFFLINE | Прямое подключение, резервное подключение и отсутствие рабочего маршрута |
| UI / UX | Внешний интерфейс / удобство и последовательность пользовательских действий |
| Dashboard / Command Center | Сводный экран показателей и состояния сети |
| Responsive | Адаптация интерфейса к ширине и способу ввода устройства |

## Данные и бизнес-правила

| Термин | Значение |
| --- | --- |
| Tenant / организация | Изолированная организационная область данных; не отдельный пользователь |
| Scope | Область данных, в которой разрешено действие или применяется фильтр |
| RBAC | Выдача разрешений по ролям |
| Repository / репозиторий данных | Код, который выполняет операции с хранилищем и скрывает SQL от прикладного слоя |
| CAS | Условное изменение записи только при совпадении ожидаемого состояния |
| Идемпотентность | Повтор одного логического действия не создаёт второй результат |
| Транзакция | Группа операций БД, применяемая целиком или отменяемая целиком |
| Миграция | Версионированное изменение схемы или данных |
| Polling | Периодическое получение новых данных запросами |
| WebSocket | Длительное двустороннее соединение для событий |
| BFQ | Обозначение одноимённого отчёта и функционального блока в проекте; бизнес-расшифровку следует согласовать с владельцем |

## Авторизация и криптография

| Термин | Значение |
| --- | --- |
| Principal / Identity | Нормализованный участник запроса / сведения о подтверждённой личности |
| Origin | Сочетание схемы, хоста и порта веб-ресурса |
| MFA | Многофакторная аутентификация |
| TOTP | Одноразовый код на основе времени и общего секрета |
| WebAuthn | Стандарт подтверждения аутентификатором, привязанный к сайту |
| Step-up | Дополнительное подтверждение перед важной операцией |
| Recovery code | Одноразовый резервный код восстановления |
| AAL2 | Обозначение повышенного уровня подтверждения в правилах проекта; не самостоятельная внешняя сертификация |
| CSRF / XSS | Подделка запроса от лица пользователя / внедрение исполняемого содержимого в страницу |
| KEK / DEK | Ключ шифрования ключей / ключ шифрования данных |
| AAD | Дополнительные проверяемые данные, связывающие шифротекст с контекстом |
| E2EE | Сквозное шифрование: посредник не располагает ключом расшифрования содержимого |
| TOCTOU | Изменение объекта между его проверкой и использованием |
| Authenticode | Механизм цифровой подписи исполняемых файлов Windows |

## Разработка и эксплуатация

| Термин | Значение |
| --- | --- |
| ADR | Запись архитектурного решения с причинами и последствиями |
| CI | Автоматические проверки изменений в репозитории |
| PR | Запрос на рассмотрение и объединение изменений |
| RC | Кандидат на выпуск; не подтверждение развёртывания |
| Smoke test | Короткая проверка базовой работоспособности |
| Regression test | Тест, закрепляющий исправление ранее найденной ошибки |
| E2E | Сквозная проверка пользовательского сценария через компоненты системы |
| Mock / заглушка | Имитация зависимости в тесте; не настоящий внешний сервис |
| Production | Рабочая среда пользователей |
| Staging | Отдельная среда предварительной проверки выпуска |
| Backfill | Заполнение или преобразование существующих записей после изменения модели |
| Rewrap | Повторная упаковка зашифрованных данных или ключей согласно конкретной реализации ротации |
| Graceful shutdown | Завершение процесса с прекращением приёма работы и корректным закрытием ресурсов |
