## Уровни подтверждения

| Уровень | Что подтверждено | Чего он не доказывает |
| --- | --- | --- |
| Реализовано | Код существует и изучен | Что он был запущен |
| Проверено локально | Конкретная команда прошла в известном окружении | Работу на Windows или в CI |
| Проверено в CI | Есть успешный запуск соответствующей задачи | Ручную установку и реальную сеть пользователя |
| Проверено на Windows | Пройден записанный сценарий на Windows | Работу через блокируемый маршрут |
| Проверено в проблемной сети | Сценарий выполнен на затронутом ПК без обходного VPN | Работу во всех возможных сетях |

Модульный, интеграционный и сквозной тест — типы проверок, а не дополнительные уровни достоверности. Для результата записывайте версию, окружение, дату, команду или шаги, ожидаемый и фактический итог. Пропущенные тесты указывайте отдельно.

## Автоматические команды

Из корня проекта перейдите в `desktop`:

```bash
cd desktop
npm ci
npm run desktop:typecheck
npm test
```

В отдельном терминале, снова из корня проекта:

```bash
cd relay
npm ci
npm run relay:typecheck
npm test
```

Для установщика используйте Windows и [инструкцию выпуска](DESKTOP-RELEASE.md). Сборка или тесты на Linux не подтверждают NSIS, Authenticode, системные диалоги и запуск установленной программы.

## Что проверяют наборы тестов

| Область | Что важно проверять |
| --- | --- |
| Конфигурация | Приоритет переменных, значения для установленной и распакованной версии, некорректные URL |
| Состояния сети | Переходы DIRECT/RELAY/OFFLINE, повторные попытки, восстановление и устаревшие ответы проб |
| Пересылка | Методы, двоичные тела, ограничения размера, разрешённые заголовки и ошибки upstream |
| Cookie | Раздельные `Set-Cookie`, сохранение сессии, выход и повторный вход |
| Обновления | Валидация манифеста, версии, размеры, SHA-256, подпись и повторная проверка перед запуском |
| Песочница | Собранный preload загружается без неподдерживаемых многофайловых `require()` |
| Чат | Запросы проходят через relay без изменения прикладного контракта |

Используемые тестовые сертификаты описаны в [desktop/tests/fixtures/README.md](../desktop/tests/fixtures/README.md) и [relay/tests/fixtures/README.md](../relay/tests/fixtures/README.md). Они предназначены только для локальных тестов.

## Ручная проверка полного сеанса

1. Откройте приложение и убедитесь, что загрузились страница, стили, шрифты и изображения.
2. Выполните вход тестовой учётной записью, включая требуемое MFA.
3. Откройте защищённые данные и проверьте чтение через API.
4. Выполните разрешённую операцию изменения данных; проверьте CSRF и результат на сервере.
5. Проверьте важную операцию с дополнительным подтверждением.
6. Проверьте регистрацию и вход с WebAuthn в поддерживаемом окружении.
7. Скачайте CSV и откройте его с русскими названиями и значениями.
8. Обновите страницу: сеанс должен вести себя согласно серверным правилам.
9. Перезапустите программу и проверьте ожидаемое сохранение сессии.
10. Выйдите; убедитесь, что защищённые данные больше недоступны в прежнем сеансе.
11. Повторите вход другим тестовым пользователем и проверьте отсутствие данных предыдущего пользователя.

Для записывающих сценариев используйте согласованное тестовое окружение. Не применяйте тестовые сертификаты или упрощённую авторизацию в рабочей среде.

## Проверка в проблемной сети

1. Запишите версию установщика, Windows и тип подключения.
2. Отключите пользовательский обходной VPN, если он использовался для диагностики.
3. Подтвердите сбой прямого обращения к приложению обычным браузером.
4. Запустите desktop с обычной конфигурацией установленной версии.
5. Откройте диагностику и дождитесь результата прямых проб.
6. Убедитесь, что автоматический режим выбрал RELAY и указал понятную причину.
7. Пройдите вход, MFA, чтение API и разрешённое изменение данных.
8. Проверьте выход, повторный вход и перезапуск программы.
9. Убедитесь, что настройки сети других приложений Windows не изменились.
10. Сохраните обезличенный результат и отдельно проверьте возврат к DIRECT после восстановления сети.

## Чат и обновления: отдельные сценарии

Для чата проверьте список диалогов, отправку, получение, непрочитанные сообщения, повтор после временного разрыва и смену пользователя. Выполните сценарии отдельно через DIRECT и RELAY. Проверка пересылки с имитацией upstream не равнозначна чату с настоящим сервером в проблемной сети.

Для обновления проверьте обнаружение новой версии, отображение описания, загрузку, реакцию на неверную сумму, предупреждение о неподписанном файле согласно политике, явное подтверждение установки, завершение приложения и запуск новой версии.

## Исторические результаты

Предыдущая документация фиксирует локальную интеграцию настоящего relay с локальным backend, PostgreSQL и TLS. В ходе неё были найдены и исправлены обработка пустого JSON-тела и отсутствие `x-step-up-token` в разрешённом списке заголовков. Такие проверки относятся к описанному проходу, а не ко всем следующим версиям.

Также зафиксированы ручная проверка чата через DIRECT и успешное обновление `20.56.4 → 20.56.5` на затронутом ПК. Реальный чат через RELAY в проблемной сети требует собственного подтверждения. Количество тестов и их статус следует брать из актуального вывода, а не переносить из старого отчёта.

## Если Electron запускается как Node.js

Переменная `ELECTRON_RUN_AS_NODE=1` меняет режим запуска. Уберите её в терминале перед запуском Electron.

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

```bash
unset ELECTRON_RUN_AS_NODE
```

Не заменяйте этой диагностикой проверку реального сообщения об ошибке: другие причины разбираются в [общем справочнике](TROUBLESHOOTING.md).
